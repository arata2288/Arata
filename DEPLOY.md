# Деплой на Railway

Бот будет работать 24/7 в облаке, даже когда ваш Mac выключен.
Railway = удобный PaaS (Heroku-альтернатива), есть бесплатный план с лимитом часов.

## Что у вас уже готово

- `Procfile`: команда запуска для Railway.
- `railway.json`: настройки билда + healthcheck по `/health`.
- `.gitignore`: `.env`, `bot.db`, `node_modules` НЕ попадают в Git.
- `package.json` → `scripts.start`: команда `npm start`.
- `db.js` берёт `DB_PATH` из окружения → можно положить БД на персистентный Volume.
- `bot.js` слушает `process.env.PORT` → Railway сам выдаёт порт.

## Шаги

### 1. Залить код на GitHub (если ещё не залит)

```bash
cd ~/ai_projects/scrum-plane-bot
git init
git add .
git commit -m "Initial commit"
# Создать пустой репозиторий на github.com, потом:
git remote add origin https://github.com/ВАШ_ЛОГИН/scrum-plane-bot.git
git branch -M main
git push -u origin main
```

⚠️ **Перед `git push` убедитесь, что `.env` не попадёт в коммит.** Команда `git status` НЕ должна показывать `.env` в списке. Если показывает — проверьте `.gitignore`.

### 2. Зарегистрироваться на Railway

1. Открыть https://railway.com (или railway.app — оба работают).
2. **Sign In** → войти через GitHub.
3. Подтвердить email, если попросит.

Бесплатный план: $5 кредитов в месяц (около 500 часов работы небольшого бота — этого хватит с запасом).

### 3. Создать проект из репозитория

1. Кнопка **New Project** (вверху справа).
2. **Deploy from GitHub repo**.
3. Дать Railway доступ к репозиторию `scrum-plane-bot` (если в первый раз).
4. Выбрать репозиторий.
5. Railway сам определит, что это Node.js, и начнёт билд через **Nixpacks**.

Билд займёт ~1–2 минуты. Пока он идёт — переходим к шагу 4.

### 4. Добавить переменные окружения

В дашборде проекта:

1. Кликнуть на сервис (квадрат с названием).
2. Вкладка **Variables** (или **Settings → Variables**).
3. Кнопка **+ New Variable** для каждой:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | ваш текущий токен из локального `.env` |
| `ANTHROPIC_API_KEY` | ваш текущий ключ |
| `ANTHROPIC_MODEL` | `claude-sonnet-4-6` |
| `DB_PATH` | `/data/bot.db` |
| `PLANE_URL`, `PLANE_API_KEY`, `PLANE_WORKSPACE_SLUG`, `PLANE_PROJECT_ID` | если есть Plane — заполнить, иначе можно пропустить |

> ⚠️ Не копируйте `ALERT_CHAT_ID` — его теперь сохраняет сам бот через `/set_alert`.

### 5. Подключить Volume (для SQLite)

Без этого SQLite-файл будет **пропадать** при каждом редеплое.

1. В сервисе → вкладка **Settings** → раздел **Volumes**.
2. **+ New Volume**.
3. **Mount path**: `/data` (точно совпадает с `DB_PATH`).
4. **Size**: 1 GB достаточно с большим запасом.
5. **Create**.

Railway автоматически передеплоит сервис с подключённым Volume.

### 6. Дождаться зелёного деплоя

В вкладке **Deployments** видны логи билда и запуска. Когда увидите:

```
[healthcheck] планировщик запущен (каждые 5 минут)
Бот запущен
Health endpoint на :8080/health
```

— готово. Бот в эфире.

### 7. Подключить алерт-чат

В Telegram → **@Help_scrum_bot** → отправить `/set_alert` → бот запомнит чат в БД на Volume → при сбоях алерты будут приходить вам.

### 8. (Опционально) Кастомный домен / публичная ссылка

Если хотите проверить health-endpoint снаружи:
1. Сервис → **Settings → Networking → Generate Domain**.
2. Railway даст ссылку вида `scrum-plane-bot-production.up.railway.app`.
3. `https://...railway.app/health` будет отвечать `{"status":"ok"}`.

Боту это для работы **не нужно** (он общается с Telegram через long-polling, наружу не торчит).
Это нужно только для внешнего мониторинга или чтобы вы могли проверить «жив ли он».

## Как смотреть логи после деплоя

1. Сервис → вкладка **Deployments** → текущий деплой → **View Logs**.
2. Или вкладка **Observability** → **Logs** — там стрим в реальном времени.
3. Все `console.log(...)` и `[healthcheck] ...` будут видны.

## Как обновлять бота

1. Локально поменять код → `git commit` → `git push`.
2. Railway сам подхватит push и передеплоит.
3. Volume сохраняется между деплоями — БД и сохранённый `chat_id` не теряются.

## Что делать при проблемах

| Симптом | Что проверить |
|---|---|
| Билд падает | Логи `Deployments → View Logs` — обычно проблема с зависимостями |
| Бот стартует, но не отвечает | `Variables` — забыли `TELEGRAM_BOT_TOKEN`? |
| `Claude API не ответил` | `Variables` — `ANTHROPIC_API_KEY`. И что на аккаунте остались кредиты |
| После редеплоя `/set_alert` нужно делать заново | `DB_PATH=/data/bot.db` не задан, или Volume не примонтирован |
| Healthcheck в Railway красный | Проверить, что `bot.js` действительно слушает `process.env.PORT` |

Для тестового бота — бесплатного плана с запасом.
